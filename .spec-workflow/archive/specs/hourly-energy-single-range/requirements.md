# Requirements Document

## Introduction

修改后端小时能耗计算逻辑，调整生成小时时间点的规则。

**核心变更**：只修改 `EnergyCalculationUtils.calculateHourlyEnergyFromRawData` 方法的内部逻辑，其它代码保持不变。

## Requirements

### 核心需求：修改小时时间点生成逻辑

#### 原来的计算规则

**输入示例**：`startTime = 2024-01-01 08:00:00`, `endTime = 2024-01-01 11:59:00`

**原逻辑流程**：
1. 生成小时时间点：
   - 将开始时间截取到小时开始：8:00
   - 循环：while (当前时间 < endTime)，每次加 1 小时
   - 生成列表：`[8:00, 9:00, 10:00, 11:00]`（**包含 11:00**，因为 11:00 < 11:59）
2. 对每个小时时间点，计算该小时的能耗：
   - 8:00 ~ 9:00：找 9:00 之后第一条记录 - 8:00 之后第一条记录
   - 9:00 ~ 10:00：找 10:00 之后第一条记录 - 9:00 之后第一条记录
   - 10:00 ~ 11:00：找 11:00 之后第一条记录 - 10:00 之后第一条记录
   - 11:00 ~ 12:00：找 12:00 之后第一条记录 - 11:00 之后第一条记录
3. 返回 **4条记录**

#### 新的计算规则

**输入示例**：`startTime = 2024-01-01 08:00:00`, `endTime = 2024-01-01 11:59:00`

**新逻辑流程**：
1. 生成小时时间点：
   - 将开始时间截取到小时开始：8:00
   - 将结束时间截取到小时开始：11:00
   - 循环：while (当前时间 < endTime的小时部分)，每次加 1 小时
   - 生成列表：`[8:00, 9:00, 10:00]`（**不包含 11:00**）
2. 对每个小时时间点，计算该小时的能耗：
   - 8:00 ~ 9:00：找 9:00 之后第一条记录 - 8:00 之后第一条记录
   - 9:00 ~ 10:00：找 10:00 之后第一条记录 - 9:00 之后第一条记录
   - 10:00 ~ 11:00：找 **11:00 之后第一条记录** - 10:00 之后第一条记录
3. 多设备：分别计算后累加
4. 异常处理：结束电量 < 开始电量时，设置为 null
5. 返回 **3条记录**

#### 关键变化

**改动点**：修改生成小时时间点的循环条件
- 原来：`while (当前时间 < endTime)`，所以 11:00 < 11:59，会生成 11:00 时间点
- 现在：`while (当前时间 < endTime的小时部分)`，所以 11:00 不会生成

**效果**：
- 原来：8:00-11:59 返回 4 条记录（8:00-9:00, 9:00-10:00, 10:00-11:00, 11:00-12:00）
- 现在：8:00-11:59 返回 3 条记录（8:00-9:00, 9:00-10:00, 10:00-11:00，最后一条的结束时间用 11:00 之后的数据）

## 实施约束

- 只修改 `EnergyCalculationUtils.calculateHourlyEnergyFromRawData` 方法中的 `generateHourlyPoints` 方法
- 不添加新方法，不修改其他代码
- 保持方法签名不变
- 保持返回数据结构不变
